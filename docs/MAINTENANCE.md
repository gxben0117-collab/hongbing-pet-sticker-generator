# 維護手冊

更新日期：2026-05-26
目前版本：v1.34

## 版本更新流程

1. 在 `index.html` 更新 `<title>` 與頁面版本徽章。
2. 若新增腳本，優先更新 `scriptData`，再把分類放入合適的 `scriptGroups`。
3. 更新 `tests/basic.mjs`，至少檢查新增分類、群組或介面函式是否存在。
4. 更新 `README.md` 的版本與更新重點。
5. 更新或補充 `docs/` 文件。
6. 執行檢查指令。
7. 將 `index.html` 複製到 `versions/index_vX.YY.html` 作為封版快照。

## 必跑檢查

Windows PowerShell 建議使用 `npm.cmd`：

```powershell
npm.cmd run build
npm.cmd test
npm.cmd run lint
```

通過標準：

- `output/index.html` 成功產生。
- 測試全部通過。
- ESLint 無錯誤。
- `output/index.html` 的版本與 `index.html` 一致。

## 腳本資料規則

- 每個分類建議維持 10 到 16 句，方便抽樣成 4、9、16 格貼圖。
- 文案以短句為主，避免太長造成貼圖字體不可讀。
- 同一分類內避免大量重複語意，讓隨機抽選更有變化。
- 多語分類要保留原語言，不要混入翻譯指令。
- 純無字腳本只放在 `純表情無字`，避免文字模式誤判。

## 介面維護規則

- 手機版按鈕不可固定四欄；新增工具按鈕時要同步檢查 `.script-toolbar`。
- 新增搜尋或篩選功能時，要提供空狀態提示。
- 不直接維護 `output/index.html`，一律由 `npm.cmd run build` 產生。
- `index.html` 仍是正式入口；若未來拆分到 `src/`，build 腳本必須能重新輸出單檔 HTML。
